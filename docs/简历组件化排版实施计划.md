## 1. 目标与范围

把精选 DOCX 模板预处理成可控组件库，支持自定义栏目、条目增删、内容变长、顺序调整与自动续页；保留可编辑文字和主要视觉风格。VLM 继续参与视觉复核与受限修复，程序承担几何计算、重排、分页和一致性检查。

本轮只更新计划，不修改业务代码或模板。此前已认可下线独立 PDF 转 DOCX、保留 PDF 材料解析的方向；该清理作为独立工作项，不与简历排版改造混在一个变更中。

首版只支持已预处理并验收的模板。任意 DOCX 自动拆解、跨模板任意拼装、自由画布编辑器、多渲染器完全一致均不属于首版承诺。提供可编辑 DOCX 不代表用户在 Word 中任意改长文字后仍能自动执行本系统重排；再次增删内容应重新生成。

### 2.1 t109 的具体拆解起点

以下 anchor 索引来自当前原件，仅供预处理时定位，禁止作为运行时永久 ID：
- anchor 0：个人信息标题、装饰和左右信息块；现有 `header_left`、`header_right` 共用它。
- anchor 1：照片及相关图形对象；先核对图片、边框和阴影的真实所有权。
- anchor 2：教育背景；子 shape 0 是标题，子 shape 1 是正文，其他子对象含装饰。
- anchor 6：实习经历；同样包含标题和正文，正文中目前写了多条经历。
- anchor 5：校园经历；anchor 4：技能证书；anchor 3：自我评价。
- anchor 7、8：底部、顶部装饰；归入页面母版，不归入任意经历条目。

先把 anchor 2、6 各自整理为“栏目标题组件 + 可重复条目原型”。标题的图标、文字、横线仍是一个组合；条目内部保留日期、机构、角色及正文样式。复制条目不复制栏目标题，复制栏目则创建新栏目 ID 和新标题。新增“项目经历”可复用同风格通用标题与经历条目原型，不沿用“实习经历”字样或不匹配的英文标签。

### 2.2 不应直接沿用的现状

`manifest` 的 `bbox_pt` 当前只有宽高，缺少页面与坐标基准；现有组件大多对应字段，而非完整视觉栏目。`moves_with` 在这 5 份模板的现有组件中均为空，不能据此认定装饰已绑定。

`fill_resume.py` 的 `_anchor_rect` 直接读取位置偏移，未解析 `relativeFrom`；t026 实际混用 page、paragraph、margin、column。`_shift_anchor` 同时调整外层 anchor 和内层 shape 偏移，必须用分组变换样例核验是否重复移动。`_resize_component` 同时修改子框与外层 extent，不能直接视为正确的组合伸展算法。

`_clone_component` 当前复制完整 drawing，然后寻找第一个文本框填值；t109 栏目标题在正文之前，存在填错槽位的风险。现有高度估算采用字符宽度近似；模板部分字号为空，不代表实际没有字号。上述是代码级风险发现，不是已完成的运行时缺陷复现。

现有 typed contracts 仍以 `fields: dict[str, str]` 和受限 changes 为主，不能完整表达栏目、条目及分页策略；旧 prompt 又要求固定框、缩至 9pt 或精简，需在新版接入时同步消除冲突。

## 3. 核心方案：一次预处理，重复确定性排版

推荐保留模板的 DrawingML 风格资源，建立语义上的顺序布局，最后编译为按页放置的 DOCX 组件。先对 t109 做小规模验证，不承诺未经实测的通用坐标转换器。若测量或分页验证失败，再评估“装饰保留、正文改为原生段落/表格流”的方案；不能由实现者静默换路线。

处理链：原始模板 → 预处理组件包 → 结构化简历内容 → 测量与布局计划 → 候选 DOCX → 实际渲染与机械检查 → VLM 复核 → 有界修复 → 交付。

### 3.1 模板预处理具体做什么

1. 冻结原件与 SHA-256；另建 v2 组件包，不覆盖原件、现有 manifest 或旧模板 ID 的行为。
2. 提取对象清单：所属 part、anchor、group、文字槽、图片关系、样式、位置基准、环绕、旋转及层级。仅处理实际使用的兼容分支；对 `mc:AlternateContent` 的 Choice/Fallback 制定同步或拒绝策略，禁止两套文字漏改。
3. 生成对象边界与编号叠加预览供模板制作者审核。自动聚类只给建议，首次入库明确确认标题、正文、照片框、背景和装饰的归属；不能仅按距离自动决定。
4. 组合栏目并提取条目原型。一个原型可包含多个 XML 片段和资源关系，不能要求其原本就在同一 anchor。把长空格对齐的日期/机构/角色整理为明确槽位与对齐规则。
5. 对每个 shape 定义 fixed、stretch_y、stretch_x、translate、aspect_fit/crop 等变换策略。文字只改变内容区，圆形图标保持尺寸，横线只伸长，边框随所属区域变化。正文禁止裁剪；删除的是条目或栏目。
6. 解析 group 的 off/ext/chOff/chExt 到组件局部坐标。组件放置只施加一次父变换；局部尺寸改变才调整子对象。不能把所有内外偏移都加同一个位移。
7. 处理 inherited 字体、字号、语言、段落间距、缩进、tab、项目符号、文本框内边距与行距，形成明确样式档案。未知值阻止模板认证，不能统一回退 11pt 后声称保真。
8. 保留图像、样式、编号、超链接、主题等依赖闭包；复制时按各类 ID 的实际作用域分配唯一 ID，修复 part relationship。原型与实例分离，运行时通过稳定 instance_id 定位，不能在插入后继续使用旧数组下标。
9. 为每个模板提供第一页和续页母版、可用内容区、栏目标题原型、条目原型、槽位、动作白名单及经验证的限制。预处理后的“原内容重放”通过视觉验收才准入。

| 数据 | 必需内容 | 负责者 |

内部几何统一用 pt、页面左上角原点和显式 page_index；序列化 DOCX 时再转换 EMU。逻辑内容和布局实例分开，跨页的两个实例仍指向同一 item_id。外部调用通常只给内容、顺序与策略；精确坐标仅作为模板允许范围内的覆盖项，不把 XML、任意路径或底层形状索引交给模型。

第一版新增栏目使用有限原型：经历条目、教育条目、要点列表、纯文本、技能列表。栏目名称可自定义，结构类型来自白名单；未匹配的图标使用通用图标或省略，不能因字段名不在旧 manifest 就静默丢弃整个栏目。

## 4. 高度测量、重排与分页

### 4.1 先验证可用的测量方式

优先对目标 Word 渲染路径做探针：在独立临时文档中按最终宽度与完整样式放置条目，检验文本框自动高度或文本范围几何能力是否可靠；不要假设某个 COM 属性能对全部 shape 使用。同批测量复用隔离的渲染实例，不能每个条目启动一次 Word。

若采用 DOCX → PDF 文字边界测量，必须在足够大的无裁切测量区域中渲染并对齐 item_id/文本片段，验证全部输入字符可见；最终框内已被裁掉的文字不会出现在 PDF 中，不能因“没有检测到越界文字”判定通过。处理项目符号、连字、空白、重复文本和字体替换；映射有歧义就报告不确定。

缓存 key 至少包含内容、可用宽度、全部样式、字体环境、渲染器版本和模板版本。字符宽度估算只用于初排，不能单独签发最终 passed。测量必须包含段前段后、行距、内边距、标题与条目之间的间距；预留量来自边界样例校准，不随意加固定大留白。

### 4.2 确定性排版规则

1. 先固定 profile 和母版保留区域；各内容 region 按栏目顺序排布。没有内容的可选栏目整体消失，后续栏目向上收拢；内容长度不等于段落数，必须按实际换行测量。
2. 栏目标题与第一条内容绑定；标题不得孤立在页底。先尝试整条放入，放不下则整体移到下一页；超过整页容量的单条内容按项目符号或段落边界拆分并带续接标识。
3. 单个不可分段落仍超过整页时返回明确的 `LAYOUT_UNSATISFIABLE`，附 item_id 和原因；不裁文字、不无限循环、不假装交付成功。需要段内拆分时另立样例验证后扩展。
4. 内容优先完整保留：在允许范围内压缩间距 → 重排/续页。字号默认保留模板值，只有策略明确允许才缩小且不低于 min_font_pt；不能为固定页数自动删减事实或条目。
5. 页数上限冲突时返回可解释选择：增加页数或经用户批准精简内容。首版建议自动 1–3 页作为候选默认值，仍待用户确认；不是文档格式本身的上限。
6. 创建真实 DOCX 页面承载段落和显式分页，将每页 anchor 绑定到该页承载段落并使用页内坐标；不得把 y 增加一页高度当成分页。验证空段落行高、最后分页符与页脚不会产生空白页。
7. 双栏阶段明确各栏独立的 flow 和续页规则。建议续页保留侧栏背景、姓名与简要联系方式，主栏续排；不默认重复全部个人信息，也不把主栏溢出内容塞进侧栏。

t109 示例：新增一个“项目经历”栏目，含 3 条长短不一的项目 → 共用一种栏目标题和条目原型 → 程序测量 3 条高度 → 顺序安放 → 第 3 条不够则移至续页并输出续接标题 → 技能等后续栏目继续排布。模型无需计算后续每个对象的 y。

## 5. 机械检查与 VLM 的分工

机械检查分层记录，不允许用一个 bool 掩盖未检查项目：包结构与关系有效；原件 hash 未变；槽位全部填充或明确省略；无原模板示例信息残留；输入内容无意外缺失、重复或乱序；页面与 region 边界合法；文本容量通过实际测量；页数及分页规则满足；可编辑文字未被整页栅格化。

碰撞检测针对同页的真实内容矩形，结合旋转/分组变换和 padding；文字与背景、图标与其容器可按声明包含关系重叠，正文之间不允许重叠。装饰层有独立规则，母版出血边界可豁免但正文不可。不能以“原模板已有重叠”为由豁免新增错误，也不能比较不同定位基准的原始 posOffset。

VLM 输入实际渲染页面、用户要求、组件编号映射和机械报告，检查视觉层级、密度、留白、图标协调、分页自然度、截断与残留模板文字；返回结构化 issue：page、instance_id、类型、证据和受限建议。模型只改内容计划或批准的布局策略，后端从干净组件包重新生成候选，不能逐次在已修改 XML 上叠加漂移。

建议机械重排最多 3 轮、VLM 修复最多 2 轮作为初始预算，计入现有 Runtime 步数/超时预算；之后标记失败或待处理并说明原因。无 vision 时保留机械结果、`visual=not_run`，不可签发“视觉已通过”；正常高质量路线要求实际视觉复核。输入内容、布局、字体、渲染器或产物 hash 变化后，旧视觉通过状态失效。

渲染超时应清理本任务创建的 Word 实例和临时资源，不能终止用户已有 Word 会话。记录真实渲染后端与版本，不把 fallback 后的结果冒充 Word 基线。输出 QA 日志只记录必要定位和摘要，不落完整简历个人信息。

### 6.1 应用内 agent 的编辑工具闭环

目标：agent 调整组件位置、大小或内容后，一次工具调用获得候选产物、机械检查和实际渲染图，随后看图继续调整或确认。不要求 agent 手动写文件、调用多个底层脚本或自行寻找截图。以下工具名为建议名；优先扩展现有 prepare/generate/repair，避免重复入口，最终 schema 在 P2 实现前固化。

| 工具职责 | 必需输入 | 返回与约束 |
| --- | --- | --- |
| `resume_prepare` 查询能力/当前布局 | template_id；编辑时 artifact_id、revision | 稳定 instance_id、page_index、region、bbox、原型、动作白名单与参数上下限；禁止返回可操作的 XML 下标 |
| `resume_generate` 首次生成 | v2 内容、模板、布局策略 | 初始候选及同版预览、机械报告，复用 repair 的结果结构 |
| `resume_repair` 批量编辑并预览 | artifact_id、base_revision、request_id、changes[]、layout_mode | 原子应用动作，测量/重排/渲染后返回新 candidate_revision；失败不覆盖已接受版本 |
| `resume_accept` 接受候选 | artifact_id、candidate_revision、expected_accepted_revision、request_id | 检查机械门、该版视觉记录和并发版本，再更新已接受版本；返回最终产物引用 |
| `resume_restore` 撤销到历史版本 | artifact_id、target_revision、expected_accepted_revision、request_id | 创建可追溯恢复版本；不删除历史或重用旧 revision；有效 QA 仅在内容与环境均一致时可复用 |

语义动作优先：插入/删除条目或栏目、移到指定组件之前/之后、修改内容、调整区域内间距。几何动作用于局部精调：`move_component(instance_id, dx_pt, dy_pt)`、`resize_component(instance_id, width_pt/height_pt)`、照片等比缩放/裁剪。仅允许模板声明的自由度、范围与页面区域；正文不允许图像式缩放或裁切。宽度改变必须重新测量文字。

`layout_mode=reflow` 为默认：语义重排或尺寸变化后推动相关 flow 的后续组件，返回实际生效位置及联动实例列表。几何移动表达为布局约束，若无法满足就失败，不能静默忽略位移。`layout_mode=local` 仅在模板允许时保持其他组件位置，越界/碰撞则拒绝。跨页移动使用目标 page/region 或语义顺序，不通过累加 y 模拟分页。同一动作禁止同时传绝对位置与相对位移。

一个批次先验证全部动作，再在隔离候选上按请求顺序修改逻辑状态，最后统一测量、排版和检查最终状态；不要因批次中间的临时碰撞提前拒绝合法交换。任何非法动作、最终碰撞、测量失败或渲染失败均令整批失败，不部分提交。以原始组件包加版本化内容/布局状态重新生成，避免反复改 XML 的累计漂移。

结果至少包含 artifact_id、base_revision、candidate_revision、status、actual_changes、affected_pages、page_count、QA、issues、preview_refs、产物 hash 与 render_id。问题指向 page/instance_id，区分版本冲突、非法动作、无法排版、测量失败、渲染失败和视觉待处理。若候选可渲染但机械失败，可附诊断图及失败候选引用；该候选不可接受或交付，只能作为修复输入。

### 6.2 图片必须进入模型视觉输入

自动渲染后，工具结果通过 Runtime/provider 的真实多模态协议向支持 vision 的 agent 传入图像内容；本地路径、URL 文本或前端可见预览不等于模型已收到图片。若 provider 不支持 tool 消息携图，由适配层以支持的图像消息传递，并保留 tool_call、artifact、revision 和 render_id 关联；不能只在 prompt 中声称图片已提供。

默认返回受影响页面的完整预览；内容重排或分页变化时加入相关前后页及页数变化说明。局部高清裁图作为补充，不能只给裁图而隐藏整体布局。显示组件编号时另附标注图，不污染交付文档。首次生成及最终接受前确保当前版本全部页面有有效视觉覆盖记录，未变页面可按图像 hash 与环境一致性复用检查。

图片尺寸、单次页数、载荷大小及渲染超时纳入能力预算，P2 通过真实 provider 探针确定具体数值并固化配置。超过单次预算返回 remaining_pages 和 revision-bound 预览读取入口；agent 必须补看相关页后才能记录视觉通过。不得因截图被截断、传输失败或未消费而标记完整视觉检查。

无 vision 时返回可供前端展示的预览与机械报告，明确 `visual=not_run`；接受规则遵循已有无 vision 降级策略，不冒充视觉验收。正常视觉路线由 agent 看图后记录结构化结论，再 accept；人工确认只在用户选择或规则冲突时请求，常规候选接受不要求每次人工点击。

### 6.3 候选、版本与并发

每个 revision 不可变，记录父版本、内容/模板/布局/产物/图像 hash 与渲染环境；维护已接受版本指针和当前可编辑候选。base_revision 必须是当前可编辑版本，过期请求返回 VERSION_CONFLICT 并告知当前版本，不能悄悄编辑另一个版本。修复失败候选时显式以该候选为父版本，已接受产物保持不变。

同 request_id、同载荷的重试返回原操作状态/结果，不重复移动或复制；同 ID 不同载荷拒绝。accept/restore 使用版本比较后原子更新，渲染期间出现新编辑也不能让旧任务覆盖新版本。超时后保留可查询操作状态，避免不确定重试制造重复候选。

接受只面向明确 candidate_revision；机械门从真实报告读取，视觉记录必须与该版 render_id/页图匹配。任意内容、布局、字体或渲染环境变化使相关 QA 失效。初始自动修复仍遵守 §5 的轮数与时间上限，失败后提供可解释结果，禁止无限循环。

## 8. 验收矩阵

| 样例 | 必须满足 |
| --- | --- |
| 原内容重放 | 与同渲染器原件基线对比，字体/颜色/装饰/主要对齐保留；差异区域有解释与视觉审核 |
| 0/1/多条经历、删除整个栏目 | 无示例文本残留、无孤立标题、装饰同步移动，内容顺序正确 |
| 增加项目/论文/志愿栏目 | 使用合法原型与新标题，全部内容进入输出；不依赖旧字段白名单 |
| 中英混排、长机构名、长 URL、粗体、项目符号 | 测量采用真实样式；无裁切；日期和角色槽不互相覆盖 |
| 同页临界长度与跨 2–3 页 | 临界页底样例逐步增加文字测试；无越界、空白末页、孤立标题或丢失条目 |
| 一条经历超过整页 | 按批准边界续接；不可拆分时可解释失败，不能无限重试 |
| 背景覆盖/正文碰撞/跨栏/出血 | 合法背景包含通过，真实正文碰撞失败，region 约束有效 |
| 连续复制、删除、重排、照片替换 | ID 和 relationships 正确，正文槽填充准确，后续修改仍定位同一 instance |
| 字体缺失、渲染失败、VLM 不可用 | 显式记录失败或未运行，不伪造 QA，不触碰用户 Word 会话 |
| 重复生成与旧任务 | 同输入得到相同语义布局；不要求 DOCX ZIP 字节相同；旧 fields、照片和历史产物可用 |
| agent 调整位置/尺寸后收图 | 真实模型请求中含该候选图像，agent 能引用图中组件问题继续调用修复；只有前端图片或路径不算通过 |
| reflow 与 local | reflow 返回真实联动结果；local 保持其他组件且非法碰撞拒绝；宽度变更重新测量，不静默丢弃动作 |
| 批量动作与失败回滚 | 合法批次按最终状态验收；任一步失败不部分提交，不覆盖已接受版本；诊断候选不可 accept |
| 过期请求、重试与并发 | 旧 base_revision 拒绝；同 request_id 不重复生效；旧渲染/accept 不覆盖新版本 |
| 预览与 QA 版本一致 | 图像、产物、机械报告及视觉记录绑定同 revision/render_id；旧截图或旧视觉通过不能接受新产物 |
| 分页与图像预算 | 页数变化返回相关页；载荷超限可按版本补看；最终全部页面有有效视觉覆盖或明确降级状态 |
| 确认与撤销 | accept 受机械/视觉策略约束；restore 生成可追溯版本，保留历史并校验 QA 可复用条件 |

布局计算写纯单元测试，XML 包处理写关系/样式/ID 的集成测试，实际模板渲染写有环境标记的端到端测试；不能全用 mock 然后声称视觉通过。重点扩展现有 `tests/test_phase5_resume_components.py` 与 `tests/test_phase4_resume_service.py`，并覆盖 Runtime 交付门相关用例。

机器硬门：必保留文本覆盖完整、非许可正文重叠为零、正文超出 region 为零、残留示例字段为零。文字覆盖按结构化片段验证，不以整份字符串粗暴匹配代替。几何测量误差阈值建议先以 1pt 为探针目标，再由 P1 临界样例决定；视觉相似度不先设未经校准的“95%”指标。

性能记录同环境的首次测量、缓存命中、整份生成耗时、渲染次数、VLM 修复次数，与旧路线相同输入比较。目标是减少无效修复并保持内容完整；具体时间 SLO 由 P1 实测后确定，不虚报速度或保真率。

## 9. 交给其他 agent 的执行约束

此计划不绑定作者或模型。可靠交接依赖清晰边界、真实样例与独立审查，不能保证某个 agent 必然优于另一个，也不能因为代码多或测试全绿就省略实际文件验收。P0–P1 由用户交给其他 agent 实施，计划作者进行 review；本次计划更新没有启动新的委派。

当前继续完成 P1 剩余修订，评审通过且用户授权后才交接 P2。接手者先读取用户 AGENTS.md、personal-engineering、本计划、现有受控工具重构计划中简历相关部分，再按表中路径检查实时实现。当前工作区已有大量未提交变更，包括 resume 的 Service、typed contracts 与脚本修改；不得 reset、覆盖、还原或将它们当成本次实现成果。

实现者只能修改当前批准阶段需要的简历领域文件与测试；原始模板只读。不得顺手重构 DOCX/PPT/PDF 服务，不得删除 PDF 功能，不得改动本计划来降低验收标准。遇到必须换排版路线、替换主要依赖、调整范围或无法通过探针的情况，提交证据和选项，由用户决定后更新计划。

每阶段交付：变更文件与职责、相对接手基线的差异、测试命令及实际结果、输入内容、生成 DOCX/PDF/页面预览、结构/机械/视觉报告、尚未通过项及环境限制。不能用口头“效果很好”代替产物，不能把未运行检查写成通过。

交接指令建议：请依据本计划与最新评审继续修订 P1，保留现有未提交修改和模板原件，提交真实样例、失败反例与误差解释后停在评审关卡。P2 获授权后，按 §6.1–6.3 实现工具和视觉闭环，提交一次真实 agent 编辑、收图、复核、修复、接受的版本关联轨迹；不得等到 P5 才验证多模态传递，也不扩展其他文档领域。

架构评审重点：复制是否重复标题；原型是否真的独立；坐标变换是否只执行一次；第二页是否是真实页；文本完整性是否包含被裁掉内容的检测；不满足页数时是否诚实失败。用户可让本计划作者或其他独立审阅者检查这些产物，不必让计划作者承担全部编码。
