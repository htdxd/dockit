# DocKit Resume：开源定位与优化报告

日期：2026-09-20。名称按用户决定暂用 DocKit Resume，发布许可已改为 AGPL-3.0。比较基于官方仓库和文档的静态核查，没有安装竞品运行同一份简历，不对竞品成品质量打分。

## 产品判断

中文模板、AI 改稿、自定义栏目和 DOCX 导出均有现成项目支持，不宜单独宣传为独有能力。推荐定位：**面向中文简历，以用户真实材料为依据，生成可继续编辑、经过实际 Word 排版检查的 DOCX/PDF，并支持自然语言局部修改。**

差异应由同输入、同要求的样例和可复现测试证明；没有基准数据前，不宣传“首稿成功率 95%”“无损迁移”或“完全无人验收”。

## 用户指定的 openResume

核查仓库：[jonbrown66/openResume](https://github.com/jonbrown66/openResume)，参考提交 `68f241f60fa7a85dce8e0d2f041fe86470d50e01`。

| 方面 | 源码可确认的行为 | 对我们的启发 |
|---|---|---|
| 模板与编辑 | 4 个模板 classic/minimal/standard/sidebar；Markdown、可视化编辑与自定义 CSS | 直接编辑与即时反馈比每次询问模型更灵活 |
| 字段 | 章节标题和正文自由；顶层 name/title/contact/image，条目 heading/meta/organization/content 固定 | 自由文本和结构化字段互补，不能将“自定义章节”视为完整字段模型 |
| GitHub 与指标 | 没找到专门 Stars/Forks 指标组件；可在正文手写链接、数字与 Markdown | 我们可让指标附属于项目，跨模板保留语义并独立强调 |
| AI | 浏览器请求模型，传当前完整 Markdown、用户指令及最近 6 条对话；返回 reply + 整篇 markdown，计算 diff 后由用户应用 | 借鉴改动预览；不要照搬整稿替换作为局部修改主路径 |
| PDF | DOM/CSS 由 Puppeteer/Chromium 打印 A4 | 跨平台部署更简单，是我们 Word 依赖的真实竞争劣势 |
| DOCX | docx 库生成原生 DOCX，但与网页独立排版；Letter 页面；standard/sidebar 走兜底模板；正文未实现 Markdown 行内粗体、链接及 HTML 高亮转换 | 不能因“支持 DOCX”就假设跨格式保真；我们应持续验证样式和超链接 |

证据：[数据类型](https://github.com/jonbrown66/openResume/blob/master/src/types/resume.ts)、[渲染器](https://github.com/jonbrown66/openResume/blob/master/src/components/ResumeRenderer.tsx)、[AI 请求](https://github.com/jonbrown66/openResume/blob/master/src/utils/resumeAssistant.ts)、[修改应用](https://github.com/jonbrown66/openResume/blob/master/src/components/AssistantWidget.tsx)、[DOCX 导出](https://github.com/jonbrown66/openResume/blob/master/app/api/export/docx/route.ts)、[PDF 导出](https://github.com/jonbrown66/openResume/blob/master/app/api/export/pdf/route.ts)。该项目为 MIT；生成 DOCX 不需要安装 Word。

## 应保持的优势

1. **真实 Word 测量与输出同源**：字号、强调和内容变化都进入测量，避免网页好看但 DOCX 换行不同。
2. **语义工具与机械 QA**：模型决定内容与强调，代码负责几何和版本；保留不可变候选、局部编辑、幂等以及来源检查。
3. **中文单页质量**：照片比例、基本信息对齐、栏目间距、项目标题/性质与技术栈分层，继续作为可回归的指标。
4. **首稿前自动修复**：不要为追求可视化 diff 反而强制用户每一步确认；差异预览应是可选查看，不增加满意度关卡。

## 短板与推进优先级

| 优先级 | 需求缺口 | 建议与验收方式 |
|---|---|---|
| P0 | 多材料可能漏读，图片反复占据上下文 | 首次生成前统一解析/转录；未识别显式标注。固定多证书样例验证材料覆盖、手动输入与问答保留 |
| P0 | 发布来源与隐私风险 | 清理已暴露凭据及历史对话；检查第三方许可、模板素材；准确披露 AI/MinerU 云传输 |
| 暂缓 | 用户缺少直接编辑入口 | 借鉴 Reactive Resume 的字段表单和 openResume 的修改预览；用户决定暂不推进直接编辑入口；未来仍可共用后端语义契约 |
| P1 | 任意亮点难以突出 | 先支持链接、项目指标、主题色与粗体；位置使用固定语义槽位，避免无约束任意坐标。更复杂同行徽章、部分句子高亮再按样例扩展 |
| P1 | “首稿合格”缺少量化 | 建立脱敏中文基准：应届、工作多年、多证书、无照片、长链接、信息不足、密集项目。统计首次候选机械通过率、自动修复后交付率、事实遗漏、平均调用数及费用，分别报告 |
| P1 | 只有两套认证模板 | 用户从图库选 3–5 套后逐套组件化；统一源数据在全部模板上回归。暂不承诺任意上传模板自动组件化 |
| P2 | Word 限制平台与并发 | 保留高质量 Word 引擎；先抽象已存在的测量/渲染边界，未来评估无 Office 路径，公开质量差异。WPS 不作为未经验证的替代 |
| P2 | 内容可移植性不足 | 支持版本化简历 JSON 导入/导出，字段随模板切换保留；可参考 YAMLResume 的内容/渲染分离 |
| P2 | 岗位适配反馈不足 | 接收用户粘贴 JD，解释选用哪些经历及依据；不做不可靠的“ATS 通过率”承诺 |

- 收敛到简历：删除通用文档/PPT 专用实现与入口，保留简历公共渲染；移除 python-pptx、openpyxl、mammoth、skia-pathops、uharfbuzz 五项直接依赖。
- 展示名 DocKit Resume；保留旧应用 ID 与内部目录兼容；去掉欢迎性宣传和“数据只在本地”的错误断言。
- 首次上下文提供完整解析文字、图片转录和来源；图片识别按文件串行执行，使用现有模型 SDK 重试。未启用视觉或不支持格式时明确标注未识别，不伪造结果。
- 自定义个人字段与项目 details 支持 link、emphasis；Stars/Forks 紧凑放在项目性质之前，与项目名称共用标题行，不挤占正文行数；技术栈仍在第二行，其余长链接可单独成行。用户数据不联网查询。尚未实现任意坐标、任意颜色或网页直接修改整份简历的表单。
- 开源 README、AGPL-3.0 与第三方声明、忽略规则整理。未修改仓库可见性、未推送、未自动清理远端历史。

## v0.2.0 发布阶段与后续顺序

- P0 材料入口：首次上下文包含全文、图片转录、逐文件 reading_status 和需要补充的清单。多证书、手动输入与来源保留有固定回归；不把转录成功当作事实百分之百正确。
- P0 发布来源：AGPL-3.0、源码入口、依赖许可及对应 PDF 引擎源码归档已准备；模板照片由自绘占位图替代，文字及 PDF 坐标与替换前完全相同。未开放的模板退出分发。
- 发布阶段后端非 e2e 回归 613 项通过（移除未开放模板的退役用例、增加发布素材检查），前端 39 项通过。独立打包运行库通过 Word 身份、t001/t109 实测、PDF 与 PNG 功能检查。安装包未代码签名。

下一批优先解决“任意亮点难以突出”，**暂缓直接编辑入口**：

1. 扩展现有语义编辑：支持对机构、角色、技术栈、正文指定短语强调。参数沿用目标条目 ID，正文额外指定段落和原文片段；找不到原文时明确返回错误，不猜位置或改写正文。
2. 区分加粗、主题色、浅色底纹三种含义；默认少量突出贡献与成果。用户明确要求优先，不强制把所有条目都改成相同强调密度。
3. Stars/Forks 继续与项目性质共用标题行；其他指标允许同一行紧凑呈现，长链接按实际测量换行。每次样式变化仍走 Word 测量，不牺牲对齐和完整性。
4. 用两模板的 20 个固定样例验证：短/长项目名、长链接、不同位数指标、正文短语高亮、撤销强调、局部改字后样式保留。要求内容/数字/来源不被格式操作改变，机械 QA 通过，再做小模型真实调用评估。

完成后再推进脱敏首稿质量基准和下一批模板。JSON 导入导出、跨平台渲染属于后续工作，当前不引入通用办公功能或任意坐标编辑器。
