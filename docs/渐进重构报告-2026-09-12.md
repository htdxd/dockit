## 架构变化

| 领域 | 重构前 | 重构后 | 维护收益 |
| --- | --- | --- | --- |
| 文件操作 | 多个服务各写 JSON、计算摘要 | 共享 `tools/workspace.py`，保留唯一临时文件及 Windows 替换重试 | 修复基础文件操作只需维护一份实现 |
| 文档渲染 | 简历与 DOCX 各一份几乎相同的渲染脚本 | 共享 `docx_render.py`，两处旧脚本各保留 12 行 CLI 入口 | Word/LibreOffice/Poppler 管线集中维护，旧调用不变 |
| 模型工具 | dispatcher 手工构造请求，运行时另列工具名 | Pydantic 契约校验请求，枚举及批量上限复用；路由从可见 schema 派生 | 减少同一参数的重复转换与工具名遗漏 |
| 工具结果 | 结果转 JSON 后再解析判断成功；重复完成日志 | 使用 dispatcher 返回的状态元数据；统一完成事件与日志 | 少一次往返转换，结果语义保持一致 |
| 简历版本 | 一个服务文件混合旧模板、新编辑、版本文件和锁 | legacy 服务、v2 服务与组合式 `ResumeStore` 分离 | 版本与幂等存储可独立定位和验证，旧导入兼容 |
| 简历生成 | 生产服务直接依赖探针场景与仓库路径 | 生产 `pipeline.py` 接受模板路径，证据场景留在 `generate.py`，t109 映射集中 | 模板资源与生产编排分离，安装目录可用 |
| 处理进程 | 简历 v2 测量/渲染绕过统一 runner | 测量、首次间距探测、渲染接入 `ProcessRunner` 与取消分发 | 活动处理进程可被应用取消，执行失败不继续下一阶段 |
| Provider | 重复探测编排与错误分类 | 共享小型探测辅助函数；协议适配保持独立 | 不同协议只维护自身请求结构 |
| 前端 | `main.ts` 混合设置、探测、任务及成果 | 入口组装设置控制器、任务控制器、成果模块与发送函数 | 状态通过显式接口访问，事件消费边界明确 |
